# Thread

사람과 AI가 같은 프로젝트에서 일하고, 이전 대화를 읽지 않아도 근거를 확인해 업무를 이어받는 PC 중심 협업툴의 **격리 시안**이다.
이 저장소에는 기존 Thread 자료가 없었다(2026-11-28 확인: 브랜치는 `main`뿐, `thread` 관련 파일 없음). 그래서 가상 데이터로 검증할 수 있게 새로 만들었다.

## 실행

의존성이 없다. Node 22 이상.

```bash
node thread/server.js            # http://127.0.0.1:8770
node --test thread/test/core.test.js   # 구현자의 자체 규칙 시험(참고 자료)
```

- 데이터는 `thread/data/state.json`에 저장된다(gitignore). 지우면 가상 데이터로 다시 시작한다.
- 로그인은 없다. 오른쪽 위 **시연용 · 보는 사람**에서 가상 인물을 바꾼다. 실제 인증은 후순위 요구사항 ‘접근 권한’에서 다룬다.
- 같은 메뉴의 **다음 저장 한 번은 응답 끊기**로, 저장은 됐지만 응답을 못 받은 상황을 만들 수 있다.

## 구조

| 파일 | 역할 |
| --- | --- |
| `core.js` | 업무 규칙 한 벌. 열람 권한, 중복 저장 방지, 검증 단계 계산, 가상 데이터. 서버와 브라우저 시연본이 같은 파일을 쓴다. |
| `server.js` | `/api/*` 요청을 `core.handle()`에 넘기고 상태를 파일에 저장한다. |
| `public/` | 화면(HTML·CSS·JS, 빌드 없음). `window.THREAD_DEMO = true`이면 서버 없이 `core.js`를 직접 쓴다. |
| `test/core.test.js` | 규칙 시험. |

## 규칙

- **열람 권한**은 `core.js`의 `canSee()` 한 곳에서, 이름이 아니라 사용자 id로 판단한다. 볼 수 없는 업무는 없는 업무와 같은 응답(404)을 받는다. 볼 수 없는 자료는 존재도 알리지 않는다.
- **저장 요청**에는 요청 키(`Idempotency-Key`)가 꼭 있어야 한다. 같은 키로 다시 오면 처음 결과를 그대로 돌려준다. 화면은 재시도할 때 같은 키를 쓴다.
- **검증 단계**는 구현 · 제3자 기능 검증 · 실사용자 검증 · 운영 배포 네 가지이며 서로 별개다. 완료 조건을 바꾸면 기준 버전이 올라가고, 이전 결과는 ‘종전 기준’으로만 보인다.
- 구현한 담당자는 제3자 기능 검증 결과를 남길 수 없다. AI는 실사용자 검증과 운영 배포 결과를 남길 수 없다.
- 현행 기준의 제3자 기능 검증이 통과해야 업무를 ‘완료’로 바꿀 수 있다.
- **상태와 진척은 저장하지 않고 계산한다.** 요구사항 상태는 연결된 업무에서, 진척은 완료한 요구사항 수에서 나온다. 커밋 수나 시험 횟수는 세지 않는다.
- AI 조회가 실패하면 마지막 결과는 남기고 현재 상태만 ‘확인 안 됨’으로 바꾼다.

## 요구사항과 검증 현황

요구사항 목록(후순위 포함)과 검증 상태는 문서가 아니라 Thread 안의 **‘Thread 만들기’ 프로젝트**(`core.js`의 `p0`)에서 관리한다. 검증 결과가 나오면 그 프로젝트의 기록을 고친다.

- 실제 첫 사용자 검증(비개발자·개발자·AI 도구 첫 사용자)은 **미검증**이다. 실제 참가자가 필요하며, AI가 사용자 역할을 대신한 결과는 세지 않는다.
- 운영 배포는 하지 않았다.

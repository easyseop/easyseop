# 사람이 추적할 수 있는 보고

## 왜 필요한가
AI는 작업을 구분하려고 "68zr", "309" 같은 번호를 붙이고, 역할에 "새 맥 실행자", "코덱스 대행" 같은 이름을 지어 붙인다. 이것은 AI가 일하는 방식이지 사람이 일을 기억하는 방식이 아니다. 사람은 번호가 무슨 일이었는지 매번 되짚어야 하고, 자잘한 중간 단계가 섞이면 정작 자기가 정해야 할 일을 놓친다.

## 이름
- 작업을 번호나 약어로 부르지 않는다. 무슨 일인지 드러나는 이름으로 부른다. 예: "용어표 초안 작성", "지도 장면 설명 검토".
- 번호가 꼭 필요하면 이름 뒤 괄호 안에 한 번만 붙인다.
- 사람·AI·역할에 새 이름을 지어 붙이지 않는다. 원래 이름을 쓴다(Claude, Codex, 담당자 이름). 그 세션에서만 통하는 별칭은 쓰지 않는다.
- 같은 작업은 보고마다 같은 이름으로 부른다.

## 보고에 넣는 것
1. **끝난 것**: 무엇이 되었고, 무엇으로 확인했는지.
2. **막힌 것**: 무엇이, 왜, 누가 풀 수 있는지.
3. **사람이 정할 것**: 질문과 선택지, 각각 고르면 어떻게 되는지.
4. **다음**: 누가 무엇을 하는지.

## 보고에 넣지 않는 것
- 작업 사본 만들기, 파일 옮기기, 재시도 같은 중간 단계.
- 실행자 배정표, 대기 중인 내부 작업 목록.

이런 내용은 작업 기록(파일이나 기록 도구)에만 남기고, 사람이 물으면 그때 보여 준다. 빼는 기준은 "사람이 이것을 알아야 다음 행동이 달라지는가"이다. 달라지지 않으면 내부 기록이다.

## 형식
- 사람이 할 일을 맨 위에 둔다.
- 한 항목은 한두 문장. 표는 비교할 것이 있을 때만 쓴다.
- 지난 보고와 달라진 것만 쓴다. 그대로인 것은 "변동 없음" 한 줄로 끝낸다.
- 확인하지 않은 것을 끝난 것으로 쓰지 않는다. "했다"와 "확인됐다"를 구분한다.

## 점검
보고를 보내기 전에, 이 대화를 처음 보는 사람이 읽는다고 생각하고 다시 읽는다. 뜻을 알 수 없는 번호·약어·별칭이 하나라도 있으면 풀어 쓴다.
